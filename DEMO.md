# Демонстрация проекта за 5–7 минут

1. Запустите `python3 main.py`.
2. Пассажиры → Добавить: ID `1`, имя `Ali`, телефон `+992900000001`.
3. Водители → Добавить: ID `1`, имя `Muhammad`, телефон `+992900000002`,
   марка `Toyota`, модель `Corolla`, номер `1234AB01`, категория `standard`.
4. Заказы → Создать: пассажир `1`, тариф `1`, расстояние `6`.
   Программа покажет `28` сомони. Подтвердите вводом `1`.
5. Заказы → Принять: ID заказа `1`, ID водителя `1`.
6. Водители → Свободные: водитель занят, список пуст.
7. Заказы → Начать поездку: заказ `1`, затем Завершить: заказ `1`.
8. Статистика → Выручка: `28` сомони. Водитель снова свободен.
9. Создайте второй заказ и отмените его. Выручка остаётся `28`.
10. Выйдите через `0`, запустите программу снова и покажите сохранённые заказы.
11. Завершите демонстрацию запуском тестов:

```bash
python3 -m unittest discover -s tests -v
```

Если данные уже существуют, используйте свободные ID и смотрите ID созданного
заказа в выводе — он генерируется автоматически.

## Что объяснить по коду

- `Order` управляет статусом одного заказа, `TaxiService` координирует заказ
  и водителя. Поэтому завершение и освобождение водителя находятся в сервисе.
- `order.driver_id` хранит число, а не целый объект водителя.
- `find_order()` возвращает `None` после всего цикла, не после первого несовпадения.
- Исключение останавливает недопустимое действие; меню ловит его и продолжает работу.
- JSON хранит словари; `from_dict()` восстанавливает полноценные объекты.
- Сохранение пишет временный файл и заменяет основной только после записи.
- `@log_action` оборачивает метод, записывает время и название успешного действия.
- Выручка суммирует только `completed`; отменённые и новые заказы не учитываются.
